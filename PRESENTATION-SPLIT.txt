    Q: How is the chart drawn without a library?
    A: In paintComponent with Graphics2D. I find the minimum and maximum in the
       series, scale each value into pixel coordinates, and call drawPolyline.
    Q: What is your min and max calculation for?
    A: To auto-scale the Y axis to the data, plus 10% padding so the line does
       not touch the edges. If all prices were identical, range would be zero and
       we would divide by zero, so the padding has a minimum of 0.05.
    Q: Why is the history limited to 120 points?
    A: To keep memory and drawing time constant no matter how long it runs. It is
       a rolling window - we add the newest and remove the oldest.

    Q: Does the rule actually run?
    A: Not yet - this build stores and manages rules. The evaluation engine is

    Q: Why is a condition a separate class?
    A: A condition is meaningless on its own, so RuleCondition is nested inside
       SurveillanceRule. That keeps the two concepts together and stops the model

    Q: How does the tree change the form?
    A: The right side is a CardLayout, which shows one component at a time by
       name. Selecting a tree category calls show(cardHolder, categoryName).

    A: They are different activities. Replay must be able to run, pause and
       change speed independently of the live feed. The market timer would keep
       ticking while replaying.
    Q: What is a ButtonGroup for?
    A: It links radio buttons so selecting one deselects the others. Without it
       they would all stay selected, which would be wrong.

PART 5 - SHARED ANSWERS: ALL THREE OF YOU MUST KNOW THESE
################################################################################

  These are architecture questions. Any of you may be asked any of them. If you
  cannot answer an architecture question about your own project, it looks bad.

  Q: What is the architecture?
  A: Four layers - gui, service, model, util. Dependencies point one way only:
     panels use services, services use models, models use nothing. That is why
     panels contain no business logic and the code is easy to explain.

  Q: What happens in one market tick?
  A: A javax.swing.Timer fires on the Event Dispatch Thread and calls tick().
     It moves every price, updates the quotes and volumes, matches waiting
     orders, cancels stale ones, then calls onMarketUpdate on every listener. The
     Market Data panel refreshes, SurveillanceService may raise an alert, and
     AnalyticsService appends to its history. All on one thread, in order.

  Q: Why javax.swing.Timer and not a Thread?
  A: Swing is not thread-safe - only the Event Dispatch Thread may touch
     components. Timer fires on the EDT, so every panel can update directly with
     no locks and no invokeLater. A background thread would have risked random
     GUI corruption.

  Q: Why is there only one timer?
  A: Because there is one market. If each panel had its own clock, two screens
     could show different prices at the same moment. One clock means one source
     of truth. (Replay is the deliberate exception - it replays history, which is
     a separate activity.)

  Q: What design pattern did you use?
  A: The Observer pattern. MarketDataService defines a MarketListener interface,
     and panels and services register themselves to be notified on every tick.

  Q: Where is the business logic?
  A: Entirely in service/. The panels only build components and react to events.

  Q: How would you add a database?
  A: Only DataStore and SettingsStore would change. The panels already talk to
     those classes rather than to files, so no GUI code changes.

  Q: How did you test it?
  A: Three ways. A headless smoke test that builds all six panels and runs the
     clock for three seconds and fails on any exception. A pre-submission checker
     that validates every file. And a rendering tool that paints each module to
     an image. Those tools found four real bugs that reading the code had missed.

  Q: What were your bugs? (A GREAT question - volunteer one, it shows maturity)
  A: Four. (1) Every table was empty because the search fields were seeded with
     their placeholder text as real text, so the filter searched for the words
     "Search symbol or company". (2) The Settings tree was squeezed to 20 pixels
     because a form demanded a 1528-pixel minimum inside a 1448-pixel pane.
     (3) The Alerts filter bar clipped its own Search and Reset buttons.
     (4) Deleted reports reappeared because we were removing from a copy of the
     list. Cite the one about your own module if you can.

  Q: Did you use any external library?
  A: No. Standard Java and Swing only - no chart library, no database driver.
     The three charts are drawn with Graphics2D.

  Q: Which is your favourite part and why?
  A: Have a REAL answer ready. Pranav: the hover crosshair on the chart.
     Shivika: the risk threshold actually filtering live alerts.
     Vishal: the JFormattedTextField enforcing the date format.
